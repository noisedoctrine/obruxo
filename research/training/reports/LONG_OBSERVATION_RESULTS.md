# Longer-observation qualification

The [plan](data/long_observations_plan.json) and [result](data/long_observations_summary.json) pass all twelve gates for the separate [long-observation profile](../LONG_OBSERVATIONS.md). Every one of the 904 training entries now has an adequate reference note under the unchanged full split ledger. This establishes attack-span coverage, not native/audio admission of every entry.

All six previously too-slow training states pass original-source native checks and fresh-process fixed-phase repeats: twelve successful diagnostic requests with exact float32 audio. Each verifies all 775 scalar controls and six nested state families. The complete recordings reach the extended frozen frontend, including audible content after sixteen seconds. The new bank retains all sixteen prior performances and adds nine long-note views; neither source membership nor source controls change.

The [initial tail diagnosis](data/long_observations_initial_tail_diagnosis.json) preserves the first failure. With a four-second tail, ten of twelve diagnostic requests were rejected for ending while the sound was still audible, affecting five sources. Their amplitude releases and effects need longer observations. The final profile uses a 32-second tail and an eighty-second frontend cap. QA thresholds and patch controls remain unchanged. The longest declared recording is 72.75 seconds, about 24.48 MiB of stereo float32 audio, within the existing 32 MiB worker cap.

The actual training loop consumes all six distinct slow sources with original requested phases, uses them through three updates, and exports/reloads the extended frontend and codec. Step-one recovery exactly matches final model, optimizer, RNG, batch RNG, replay and cursor, with zero additional renders. The frozen Basic Pitch weights/buffers remain unchanged. Peak process-tree memory including source-pool loading is 1,862,144,000 bytes (1.74 GiB), within the 8 GiB budget. This is bounded integration evidence, not useful model quality.

The [compatibility receipt](data/long_observations_compatibility.json) verifies the earlier corpus codec/pool identities, exact source entries, frozen manifest, original source contract and prior bank prefix. New contracts carry a distinct observation profile, bank digest and tail budget. Earlier serialized contracts omit the optional profile and retain their exact identities. Short-clip tensors remain bit-identical between old and extended frontends; a late-tone test proves that audio after sixteen seconds affects both feature branches. Full recordings are not cropped.

All 23 final selected local tests pass, including the new profile, source/role checks, old/new frontend boundaries, late content, checkpoint recovery, export/reload, legacy corpus/native serialization and audits. The earlier 55-test regression run also passed before the tail-budget extension. Ruff and whitespace checks pass. The [timing receipt](data/long_observations_timing.json) measures 513 seconds of diagnostic audio rendered in 31.31 seconds, about 16.39 times real time. This includes native state loading but excludes process startup, feature extraction, optimizer work and checkpoint I/O; it is not an end-to-end throughput claim.

Long recordings cost more CPU time. This optional profile is not a declaration that every ordinary training view should use a long note. The next work is an explicit authored/corpus mixture and measured sampling/throughput before broad training. Population-wide source QA, decoder refitting, useful transfer quality, Linux/Colab qualification and release remain open. No final-test audio is rendered, no model is promoted, and GitHub Actions remains disabled. Presets, dataset paths, features, audio and weights stay local; public evidence is metadata only.
