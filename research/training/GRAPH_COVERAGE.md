# Complete connection inventory under frozen patch families

The earlier combined curriculum actively supervised 326 of Vital's 431 registered connection destinations. `graph-pool` schedules every destination in training. It keeps all 32 source names and all 64 ordered slots, including connections that change another connection's amount or curve power.

Each frozen patch family produces four distinct states: its original curve-input source, unchanged, and three variants with one scheduled destination each. Related states inherit their original family and split. The default pool has 1,024 states under the existing 256 independent families; adding variants does not create additional independent test examples. No final-test audio is generated by pool creation or the coverage audit.

Training destinations cycle through a seeded permutation. Validation and test use separate seeded permutations, so small held-out subsets do not take the first names alphabetically. Evaluation averages related cases within their family before model selection and bootstrap resampling. A missing score prevents that family from qualifying for selection. Older pools keep their existing state-based statistics and artifact identities.

The three new variants enable generators, filters and effects, preserve the original asset vocabulary and use direct pan connections as exits. A connection targeting another connection cannot overwrite that referenced slot or its remaining source anchor. Named rate, keytrack, formant, oscillator and sample prerequisites are set explicitly. The original variant retains sparse and single-generator scenes. The output dimensions and model architecture are unchanged.

## What the checks establish

The static audit measures declared supervision: a target exists and its label is enabled. It does not establish that each target changes audio in every patch, nor that a trained model can recover it.

`run_destination_responses.py` measures native response separately. For each destination it renders a bypassed connection, a connected connection and an exact repeat. CC1 reaches the mod-wheel source before note-on. Oscillator and sampler random phases are fixed in these correctness copies, and each request gets a fresh process. Full scalar/nested readback, audio QA, repeat equality, source fingerprints and the memory limit remain required. A zero response means the declared context is unresolved; it never removes a destination from the vocabulary. Optional scalar overrides record the exact alternative settings in the plan.

Actual training renders original requested phases on demand, retains a bounded feature/label replay, and verifies interruption recovery with those identical features. It does not promise identical audio by regenerating a seed. The shared curve-input integration runner checks that both original and connection variants are consumed, all source names and slots survive in consumed graphs, recovery is exact, and exported weights load.

## Local commands

Use the dependency environment documented in [README](README.md) and previously qualified private asset/LFO banks. Keep output directories new. CPU thread limits such as `OMP_NUM_THREADS=2`, `MKL_NUM_THREADS=2` and `OPENBLAS_NUM_THREADS=2` avoid oversized numerical-library thread pools during source generation.

```text
python research/training/run.py graph-pool --asset-bank FACTORY_BANK.json --lfo-bank LFO_BANK.json --output OUTPUT_POOL
python research/training/reports/scripts/audit_capabilities.py --pool OUTPUT_POOL/pool.json --output OUTPUT_AUDIT
python research/training/reports/scripts/run_destination_responses.py --asset-bank FACTORY_BANK.json --output OUTPUT_NATIVE
python research/training/reports/scripts/run_curve_input_integration.py --pool OUTPUT_POOL/pool.json --native QUALIFIED_SINGLETON_PANEL --precision QUALIFIED_PRECISION_PANEL --output OUTPUT_INTEGRATION
```

`--count` on `graph-pool` creates a bounded prefix for diagnostics. Only the full audited pool establishes complete training coverage. `--destinations` and `--overrides` on the native runner support explicit subsets and a JSON map from destination name to registered scalar overrides. `--performance` accepts explicit authored Performance JSON, recorded in the plan, for targets requiring overlapping notes or pitch bends. Macro targets get downstream pan connections. Probe direction is chosen after overrides to avoid clamping at a control boundary, and overrides cannot change the fixed random phases. Its success status reports protocol/repeatability gates; inspect `responses_observed` and `unresolved_destinations` separately.

The [results report](reports/GRAPH_COVERAGE_RESULTS.md) records measured evidence and remaining gaps. This increment establishes data and pipeline coverage; useful reconstruction, broader corpus admission, Linux/Colab qualification and release remain separate gates. GitHub Actions remains disabled.
